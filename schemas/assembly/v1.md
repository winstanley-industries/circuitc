# CircuitC assembly v1

## Status and authority

Version 1 is the canonical Layer-3 component-population projection for one
exact product variant. Source and Design IR own variant population and
configuration. This artifact is not an assembler instruction format, host
result, or proof that a board was manufactured.

## Encoding, path, and bounds

The artifact is strict compact canonical UTF-8 JSON followed by exactly one LF,
using the field order below. Unknown, missing, duplicate, reordered,
pretty-printed, trailing, or otherwise non-canonical fields or bytes are
invalid. A consumer reserializes and requires exact byte equality.

The complete artifact is at most 67,108,864 bytes including LF and contains at
most 10,000 component rows. The row ceiling is checked before expanded row and
reconciliation validation. No partial or truncated assembly artifact is valid.
The checked aggregate complete size of all four bundle artifacts is also at
most 67,108,864 bytes and is preflighted before returning any artifact.

`variant_identity_sha256` is lowercase SHA-256 over ASCII
`CIRCUITC-PRODUCT-VARIANT-IDENTITY-V1`, one NUL byte, and exact UTF-8
`variant_path`. The only valid path is
`product/<variant_identity_sha256>/assembly.json`.

## Root object

The root has exactly these fields in this order:

| Field | Type | Contract |
| --- | --- | --- |
| `schema_name` | string | Exactly `circuitc.assembly`. |
| `schema_version` | u32 | Exactly `1`. |
| `design_name` | string | Exact safe Design artifact stem. |
| `variant_path` | string | Exact authored variant semantic path. |
| `variant_identity_sha256` | string | Recomputed variant identity. |
| `product_input_sha256` | string | Exact common digest defined by product-resolution v1. |
| `product_resolution_sha256` | string | SHA-256 of exact canonical resolution bytes including LF. |
| `build_quantity` | u64 | Exact positive variant build quantity. |
| `configurations` | array | Entries strictly sorted and unique by `key`. |
| `components` | array | Rows strictly sorted and unique by `component_path`. |

Each configuration has exactly `key` and `value`, in that order, and equals the
exact canonical variant configuration. Configuration roots must equal product
resolution exactly.

## Selected identity

A non-null `selected_identity` has exactly `logical_function`, `manufacturer`,
`manufacturer_part_number`, `package`, and `value`, in that order. `value` has
exactly `kind`, `coefficient: i64`, `exponent: i8`, and `unit`, in that order,
and follows the canonical resistance/ohm or dc_voltage/volt contract. It equals
the selected product-resolution identity exactly.

## Component row

Each row has exactly these fields in this order:

| Field | Type | Contract |
| --- | --- | --- |
| `component_path` | string | Exact canonical physical-component semantic path. |
| `reference` | string | Exact canonical Design component reference. |
| `state` | string enum | `fitted`, `not_fitted`, or `alternate`. |
| `selected_identity` | object or null | Exact selected identity, null only for `not_fitted`. |
| `per_board_quantity` | u64 | Exactly `0` for `not_fitted`, otherwise exactly `1`. |
| `total_quantity` | u64 | Checked `per_board_quantity * build_quantity`. |

Every physical Design component appears exactly once and no virtual component
appears. Rows are strictly increasing by UTF-8 byte order of `component_path`.
State, reference, selected identity, and quantity reconcile exactly with Design
and product resolution. A fitted row selects the base identity; an alternate
row selects one exact approved identity; a not-fitted row has null selection,
zero per-board quantity, and zero total quantity. Overflow is a stable failure.

## Verification and failure

The common product-input digest is recomputed from the exact domain and
canonical authoritative-input projection defined in
[`product_resolution/v1`](../product_resolution/v1.md); it is not copied from a
supplied artifact.

The strict bundle verifier independently rederives the complete physical
component inventory, state, selection, quantities, configurations, build
quantity, artifact path, variant identity, and resolution digest from Design,
the selected variant, and freshly authenticated catalog evidence. Missing,
duplicate, reordered, stale, extra, overflowed, or coordinated rows fail even
when all supplied product artifacts repeat the same alteration.

Failure returns stable machine-readable diagnostics and no partial assembly
artifact. Layer 3 does not invoke or claim acceptance by KiCad, an assembly
host, a fabrication host, or a release system.
