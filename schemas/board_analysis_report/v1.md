# CircuitC board-analysis assertion report schema v1

`circuitc.board_analysis_report` v1 maps one exact result to every authored
manufacturability assertion. It is compact canonical JSON plus one final LF,
at most 67,108,864 bytes, with these exact ordered fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `schema_name` | string | Exactly `circuitc.board_analysis_report`. |
| `schema_version` | integer | Exactly `1`. |
| `analysis_identity_sha256` | string | Exact request identity. |
| `request` | artifact binding | Exact request. |
| `result` | artifact binding | Exact result. |
| `execution_status` | string | Same `completed`, `failed`, or `unsupported` status as the result. |
| `all_pass` | boolean | True only for five complete pass outcomes. |
| `outcomes` | array | Exactly one outcome per request assertion in request order. |

Each outcome contains exactly `assertion_path`, `capability`, `outcome`, and
`evidence_role`. Completed evidence yields an independent `pass` or `fail` and
one of `erc`, `drc`, or `fabrication_manifest`. `drc_clean`,
`unconnected_clean`, and `schematic_parity_clean` deliberately name the same
structured DRC artifact but are evaluated from distinct arrays or policies
inside it. `erc_clean` is evaluated from authenticated sheet findings, while
`fabrication_inventory_complete` is derived from the bound authenticated
Layer-4 manifest. A failed result yields `unevaluated` with null evidence for
every assertion. An unsupported result yields `unsupported` with null evidence
for every assertion.

The report must contain the exact five request assertions in order. Missing,
duplicate, additional, reordered, or changed paths, capabilities, outcomes, or
evidence roles are invalid. `all_pass` is false unless execution completed and
all five outcomes are `pass`.
