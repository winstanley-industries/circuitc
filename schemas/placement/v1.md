# CircuitC placement v1

## Status and authority

Version 1 is the canonical Layer-3 physical-placement projection for fitted
components in one exact product variant. Placement remains Design IR authority;
this artifact is not derived from KiCad and is not a pick-and-place machine
format or host-acceptance result.

## Encoding, path, and bounds

The artifact is strict compact canonical UTF-8 JSON followed by exactly one LF,
using the field order below. Unknown, missing, duplicate, reordered,
pretty-printed, trailing, or otherwise non-canonical fields or bytes are
invalid. A consumer reserializes and requires exact byte equality.

The complete artifact is at most 67,108,864 bytes including LF and contains at
most 10,000 placement rows. The row ceiling is checked before expanded join
validation. No partial or truncated placement artifact is valid.
The checked aggregate complete size of all four bundle artifacts is also at
most 67,108,864 bytes and is preflighted before returning any artifact.

`variant_identity_sha256` is lowercase SHA-256 over ASCII
`CIRCUITC-PRODUCT-VARIANT-IDENTITY-V1`, one NUL byte, and exact UTF-8
`variant_path`. The only valid path is
`product/<variant_identity_sha256>/placement.json`.

## Root object

The root has exactly these fields in this order:

| Field | Type | Contract |
| --- | --- | --- |
| `schema_name` | string | Exactly `circuitc.placement`. |
| `schema_version` | u32 | Exactly `1`. |
| `design_name` | string | Exact safe Design artifact stem. |
| `variant_path` | string | Exact authored variant semantic path. |
| `variant_identity_sha256` | string | Recomputed variant identity. |
| `product_input_sha256` | string | Exact common digest defined by product-resolution v1. |
| `product_resolution_sha256` | string | SHA-256 of exact canonical resolution bytes including LF. |
| `placements` | array | Rows strictly sorted and unique by `component_path`. |

## Selected identity

`selected_identity` has exactly `logical_function`, `manufacturer`,
`manufacturer_part_number`, `package`, and `value`, in that order. `value` has
exactly `kind`, `coefficient: i64`, `exponent: i8`, and `unit`, in that order,
with the same canonical resistance/ohm and dc_voltage/volt rules as product
resolution. The identity equals the exact non-null selected resolution identity.

## Placement row

Each row has exactly these fields in this order:

| Field | Type | Contract |
| --- | --- | --- |
| `component_path` | string | Exact canonical physical-component semantic path. |
| `reference` | string | Exact canonical Design reference. |
| `selected_identity` | object | Exact non-null fitted or alternate selected identity. |
| `x_nm` | i64 | Exact Design placement X coordinate in nanometres. |
| `y_nm` | i64 | Exact Design placement Y coordinate in nanometres. |
| `rotation_degrees` | i32 enum | Exactly `0`, `90`, `180`, or `270`. |
| `side` | string enum | Exactly `front` or `back`. |

Rows are strictly increasing by UTF-8 byte order of `component_path`.
Component paths and references reconcile exactly with Design and product
resolution. Every `fitted` or `alternate` physical component appears exactly
once; no `not_fitted`, virtual, unknown, or duplicate component appears.
Coordinates remain signed integer nanometres and rotation remains orthogonal;
no floating-point, unit conversion, board-editor normalization, or host
coordinate convention enters this schema.

## Verification and failure

The common product-input digest is recomputed from the exact domain and
canonical authoritative-input projection defined in
[`product_resolution/v1`](../product_resolution/v1.md); it is not copied from a
supplied artifact.

The strict bundle verifier independently rederives fitted inventory and exact
placement from Design, the selected variant, and freshly authenticated catalog
evidence. It recomputes the path, variant identity, resolution digest, roots,
rows, and canonical bytes. Missing, duplicate, reordered, stale, extra, or
coordinated placement rows fail even when another supplied artifact repeats the
same error.

Failure returns stable machine-readable diagnostics and no partial placement
artifact. Layer 3 makes no KiCad parse, DRC, machine-import, assembly, or
manufacturing-acceptance claim.
