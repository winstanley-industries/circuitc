# CircuitC fabrication manifest v1

## Status and authority

Version 1 is the deterministic normalized result of the exact
[`circuitc.fabrication_request` v1](../fabrication_request/v1.md) executed by
KiCad 10.0.5. KiCad owns native PCB parsing and export semantics. CircuitC owns
strict native parsing, narrow date normalization, product/placement joins,
digests, and acceptance. Source and Design IR remain product and geometry
authority.

## Encoding, path, and bounds

The manifest is compact canonical UTF-8 JSON followed by exactly one LF, with
root and nested fields in schema order. Unknown, missing, duplicate, reordered,
pretty-printed, trailing, or otherwise non-canonical fields or bytes are
invalid. Its only path is
`fabrication/<fabrication_identity_sha256>/manifest.json`.

Each request, manifest, raw host file, and normalized output is at most
67,108,864 bytes. The exact native/normalized output count is 13, position rows
are at most 10,000, and the checked request+manifest+normalized-output aggregate
is at most 268,435,456 bytes. No oversized or partial bundle is valid.

The root has exactly these fields in this order:

| Field | Type | Contract |
| --- | --- | --- |

| `schema_version` | u32 | Exactly `1`. |
| `design_name` | string | Exact request Design stem. |
| `analysis_path` | string | Exact request analysis path. |
| `assertion_path` | string | Exact request assertion path. |
| `variant_path` | string | Exact request variant path. |
| `variant_identity_sha256` | string | Exact recomputed Layer-3 identity. |
| `product_input_sha256` | string | Exact recomputed Layer-3 common digest. |
| `product_resolution_sha256` | string | Exact resolution-byte digest. |
| `placement_sha256` | string | Exact placement-byte digest. |
| `catalog_evaluated_on` | string | Authenticated date used for normalization. |
| `kicad_pcb` | object | Exact request board `path` and `sha256`. |
| `fabrication_identity_sha256` | string | Recomputed request identity. |
| `request` | object | Full request `path`, `byte_length`, and exact-byte `sha256`. |
| `exporter` | object | `adapter:"kicad"`, `version:"10.0.5"`, and lowercase executable `sha256`. |

| `gerber_job` | object | Parsed normalized job binding. |

All path/length/digest bindings use exactly `path`, `byte_length:u64`, and
`sha256`, except where the specialized rows below add parsed fields.

## Gerber and job inventory

`gerbers` is strictly sorted by layer ID and contains exactly the nine layers
defined by ADR-0011. Each row has exactly `layer_id`, `layer_name`,
`file_function`, `path`, `byte_length`, and `sha256`. Paths are the request
suffixes below the fabrication root. Digests cover normalized native bytes,
including final LF.

`gerber_job` has exactly `path`, `byte_length`, `sha256`, and
`gerber_count:9`. Its strictly parsed native file attributes equal all nine
Gerber basenames, job file functions, and polarities bidirectionally. A path
alias, directory component, missing, duplicate, or extra job entry is invalid.

Every Gerber and the job bind KiCad/Pcbnew 10.0.5 and the exact Design project.
Only the recognized creation-date fields are replaced with
`catalog_evaluated_on` at midnight as specified by ADR-0011; every other byte
is preserved.

## Drill inventory

`drills` has exactly two rows, ordered `non_plated_through` then
`plated_through`. Each row has exactly `kind`, `path`, `byte_length`, `sha256`,
`tool_count`, `round_hit_count`, and `slot_hit_count`. All three counts are zero
in v1. Both native files must be exact framed KiCad 10.0.5 metric, decimal,
absolute, empty Excellon outputs with the matching X2 FileFunction. Any tool or
hit is unsupported and invalid. Creation-date normalization is the narrow rule
in ADR-0011.

## Position evidence

`position_csv` has exactly `path`, `byte_length`, `sha256`, and `row_count`.
The CSV bytes are unmodified host bytes.

`position_rows` contains every physical Design component exactly once, sorted
by `component_path`. Each row has exactly `component_path`, `reference`,
`host_value`, `host_package`, `x_nm`, `y_nm`, `rotation_degrees`, `side`, and
`state`.

The parser requires the exact KiCad header
`Ref,Val,Package,PosX,PosY,Rot,Side`. It decodes six-decimal millimetres without
floating point, maps `x_nm = PosX * 1,000,000`, maps
`y_nm = -PosY * 1,000,000`, accepts only orthogonal rotation, and maps
`top`/`bottom` to `front`/`back`. Reference, exact lowered value, footprint
library-item package, position, rotation, and side equal Design. `state` is the
exact Layer-3 `fitted`, `not_fitted`, or `alternate` population. Full-board
not-fitted host rows are evidence only and never enter canonical Layer-3
placement.

## Verification and failure

The binder never trusts caller hashes, counts, filenames, directory inventory,
executable digest, or manifest fields. It recomputes the request from Design,
catalog, product, and explicit static-or-checked compiler authority; hashes the
exact supplied executable bytes; requires the exact explicit 13-path raw map;
parses and normalizes every native file; joins all position rows; hashes every
normalized byte; and constructs the manifest. Host exit zero without these
checks is not acceptance.

The verifier reconstructs the entire expected bundle from authoritative inputs
and exact raw files and requires path and byte equality for request, manifest,
and all normalized outputs. Any stale input, malformed time field, missing,
extra, duplicate, wrong host/version/function/polarity, nonzero drill inventory,
position drift, unsafe path, digest mutation, or coordinated rewritten bundle
fails with a stable machine-readable diagnostic and no partial success.
