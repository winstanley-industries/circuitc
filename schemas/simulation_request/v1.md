# CircuitC simulation request v1

## Status and encoding

Version 1 is the active process request contract for EPIC-0003. The artifact is
UTF-8 JSON with the exact fields below, two-space indentation, and one final
newline. Unknown, missing, or duplicate fields are invalid. The request names
exactly one analysis, authenticates every assertion to be evaluated for that
analysis, and contains no raw solver IR.

Every digest is exactly 64 lowercase hexadecimal characters containing the
SHA-256 of the referenced canonical bytes. The netlist digest covers the exact
SPICE bytes. A digest of this request covers the complete canonical JSON bytes,
including its final newline.

| Field | Type | Contract |

| `schema_name` | string | Exactly `circuitc.simulation_request`. |
| `schema_version` | integer | Exactly `1`. |

| `analysis` | object | Exactly one analysis request below. |
| `assertions` | array | Assertion intent strictly sorted and unique by `path`. |

## Analysis object

| Field | Type | Contract |
| --- | --- | --- |
| `path` | string | Unique canonical analysis semantic path. |
| `kind` | string enum | `dc_operating_point`, `ac_linear_sweep`, or `transient`. |
| `netlist_path` | string | Canonical portable relative path to the one-analysis SPICE file. |
| `netlist_sha256` | string | Digest of the exact netlist bytes. |
| `map_path` | string | Canonical portable relative path to the matching SPICE identity map. |

Portable relative paths are non-empty `/`-separated normal components. They
do not begin with `/` and contain no empty component, `.`, `..`, backslash, or
NUL. The request deliberately omits a map digest: the map binds the exact
request digest, avoiding a cryptographic cycle.

## Assertion intent

Each assertion has exactly `path`, `signal_kind`, `canonical_identity`,
`sample`, `unit`, `expected`, `absolute_tolerance`, and `relative_tolerance`.
The signal-kind and unit enums, sample object, and canonical finite number
encoding are those defined by the normalized-result and report contracts.
Sample kind must match the request analysis. Tolerances are non-negative.
Because this complete intent is inside the digest-bound request, a report may
not omit an assertion or rewrite its expected value, sample, signal, or
tolerances.

## Failure behavior

An unsupported schema, backend identity, analysis kind, digest, semantic path,
or artifact path fails with a `CC-SIM-CONTRACT-*` diagnostic. Consumers may
not reinterpret unknown fields or select a nearby backend version.

Parsers and producers reject any semantically equivalent but non-canonical JSON
spelling, any contract larger than 64 MiB, or any collection larger than
10,000 entries before it can become digest-bound evidence.
