# CircuitC board-analysis result schema v1

`circuitc.board_analysis_result` v1 records one complete, failed, or unsupported
execution of a board-analysis request. It is compact canonical JSON plus one LF
with exact fields, order, types, and a 67,108,864-byte limit.

| Field | Type | Meaning |
| --- | --- | --- |
| `schema_name` | string | Exactly `circuitc.board_analysis_result`. |
| `schema_version` | integer | Exactly `1`. |
| `analysis_identity_sha256` | string | Exact request identity. |
| `request` | artifact binding | Exact request path, length, and digest. |
| `status` | string | `completed`, `failed`, or `unsupported`. |
| `tool` | object or null | Exact completed adapter identity. |
| `evidence` | object or null | Complete completed evidence set. |
| `diagnostic` | object or null | Bounded noncompletion diagnostic. |

For `completed`, `tool` contains exactly `adapter`, `version`,
`executable_sha256`, `normalizer_sha256`, and `host_runner_sha256`. `evidence`
contains exactly the `erc`, `drc`, and `fabrication_manifest` artifact bindings.
`diagnostic` is null. ERC and DRC paths are exact
`board-analysis/<identity>/evidence/{erc,drc}.normalized.json` paths.
Completed means the host produced structurally valid, authenticated evidence;
that evidence may contain dirty findings and therefore yield assertion failures.

For `failed` or `unsupported`, both `tool` and `evidence` are null and
`diagnostic` contains exactly `code` and `message`. Codes are nonempty bounded
uppercase ASCII tokens containing only `A-Z`, `0-9`, and `-`; messages are
nonempty single-line UTF-8 values of at most 4096 bytes. A noncompleted result
cannot retain a partial report, tool, or fabrication evidence object.

The completed receipt is transient but canonical. It contains exact request,
schematic, PCB, identity-map, executable, normalizer, host-runner, ERC, and DRC
SHA-256 values. The binder recomputes them before emitting this result.
