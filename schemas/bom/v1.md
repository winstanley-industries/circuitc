# CircuitC BOM v1

## Status and authority

Version 1 is the canonical Layer-3 grouped bill-of-materials projection for one
exact product variant. It is derived from validated Design IR and freshly
authenticated catalog resolution. It is not source authority, a distributor
order, availability evidence, or proof of procurement or manufacture.

## Encoding, path, and bounds

The artifact is strict compact canonical UTF-8 JSON followed by exactly one LF,
using the field order below. Unknown, missing, duplicate, reordered,
pretty-printed, trailing, or otherwise non-canonical fields or bytes are
invalid. A consumer reserializes and requires exact byte equality.

The complete artifact is at most 67,108,864 bytes including LF and contains at
most 10,000 BOM items. The item ceiling is checked before expanded grouping and
reconciliation. No partial or truncated BOM is valid.
The checked aggregate complete size of all four bundle artifacts is also at
most 67,108,864 bytes and is preflighted before returning any artifact.

`variant_identity_sha256` is lowercase SHA-256 over ASCII
`CIRCUITC-PRODUCT-VARIANT-IDENTITY-V1`, one NUL byte, and exact UTF-8
`variant_path`. The only valid path is
`product/<variant_identity_sha256>/bom.json`.

## Root object

The root has exactly these fields in this order:

| Field | Type | Contract |
| --- | --- | --- |
| `schema_name` | string | Exactly `circuitc.bom`. |
| `schema_version` | u32 | Exactly `1`. |
| `design_name` | string | Exact safe Design artifact stem. |
| `variant_path` | string | Exact authored variant semantic path. |
| `variant_identity_sha256` | string | Recomputed variant identity. |
| `product_input_sha256` | string | Exact common digest defined by product-resolution v1. |
| `product_resolution_sha256` | string | SHA-256 of exact canonical resolution bytes including LF. |
| `build_quantity` | u64 | Exact positive variant build quantity. |
| `items` | array | BOM items strictly sorted and unique by `selected_identity`. |

## Selected identity and exact value

`selected_identity` has exactly `logical_function`, `manufacturer`,
`manufacturer_part_number`, `package`, and `value`, in that order. `value` has
exactly `kind`, `coefficient: i64`, `exponent: i8`, and `unit`, in that order.
Supported kind/unit pairs are `resistance`/`ohm` and `dc_voltage`/`volt`.
Identity and canonical decimal value equal the selected product-resolution
identity exactly; no float, display value, footprint name, or package-only
match may substitute for it.

## BOM item

Each item has exactly these fields in this order:

| Field | Type | Contract |
| --- | --- | --- |
| `selected_identity` | object | Exact grouped selected identity and typed value. |
| `per_board_quantity` | u64 | Positive count of contributing fitted components on one board. |
| `total_quantity` | u64 | Checked `per_board_quantity * build_quantity`. |

Items are strictly increasing by the exact identity tuple
`(logical_function, manufacturer, manufacturer_part_number, package, value)`
using lexicographic field order and canonical numeric values. Two items may not
name the same selected identity.

Every `fitted` or `alternate` product-resolution row contributes exactly one
unit to exactly one item. Every item has at least one contributing resolution
row. Not-fitted and virtual components contribute nothing. Per-board counts
equal the complete contributing inventory, and multiplication overflow is a
stable failure rather than wrapping, saturating, or omitting an item.

## Verification and failure

The common product-input digest is recomputed from the exact domain and
canonical authoritative-input projection defined in
[`product_resolution/v1`](../product_resolution/v1.md); it is not copied from a
supplied artifact.

The strict bundle verifier rederives the expected fitted selected identities
directly from Design, the exact variant, and freshly authenticated catalog
evidence. It recomputes grouping, checked quantities, artifact path, variant
identity, and exact resolution digest, then requires canonical byte equality.
It rejects missing, duplicate, reordered, ungrouped, extra, stale, overflowed,
or coordinated items even if the supplied product artifacts agree with each
other.

Failure returns stable machine-readable diagnostics and no partial BOM. No
KiCad or manufacturing host parses or authorizes this artifact in Layer 3.
