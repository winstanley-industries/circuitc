# `circuitc.release_request` schema version 1

The release request is strict compact canonical JSON followed by one LF. The
root object contains exactly these fields in this order:

1. `schema_name`: `"circuitc.release_request"`
2. `schema_version`: `1`
3. `release_identity_sha256`: lowercase SHA-256 of the request identity
   preimage described by ADR-0013
4. `design_name`: canonical Design artifact stem
5. `variant_path`: exact selected Design variant path
6. `variant_identity_sha256`: Layer-3 variant identity
7. `product_input_sha256`: Layer-3 product-input identity
8. `source`: one artifact binding
9. `design_identity_sha256`: complete canonical Design identity
10. `catalog`: one artifact binding
11. `applicability`: closed applicability object
12. `tools`: ordered nonempty array of tool bindings
13. `artifacts`: complete path-sorted nonempty array of artifact bindings
14. `resources`: fixed release resource policy

An artifact binding contains exactly `role`, `path`, `byte_length`, and
`sha256`, in that order. `path` is a safe relative suffix beneath the derived
release root. Digests are lowercase hexadecimal SHA-256 values. The source and
catalog bindings are also members of `artifacts`; their repeated root bindings
must be exactly equal.

`applicability` contains exactly `simulation` and `routing` booleans. Simulation
is true exactly when the Design declares simulation analyses. Routing is true
exactly when the Design declares APGAR routing requests; authored route
segments do not imply it.

Each tool binding contains exactly `role`, `name`, `version`, `source_revision`,
`byte_length`, and `sha256`. A non-applicable source revision is the empty
string, not a missing field. Tool rows use the closed order `kicad`,
`analysis_normalizer`, `analysis_host_runner`, `ohmnivore`, `apgar`. The first
three are required. `ohmnivore` is present exactly when simulation is
applicable and its digest equals every checked simulation execution identity.
`apgar` is present exactly when routing is applicable and its digest equals the
checked route result, projection, provenance, and acceptance.

`resources` contains exactly `file_bytes`, `file_count`, `path_bytes`,
`consumed_aggregate_bytes`, and `emitted_aggregate_bytes`. Version 1 values are
67,108,864; 4096; 1,048,576; 1,073,741,824; and 1,073,741,824 respectively.

Unknown, missing, duplicate, reordered, non-canonical, over-limit, or trailing
data is invalid. The artifact inventory is derived from typed predecessor
bundles and must equal the complete applicable release inventory; a caller may
not add an internally consistent extra artifact. Every artifact path is a
portable canonical ASCII relative path of at most 4096 bytes; the aggregate
path-byte policy remains the `resources.path_bytes` value above.
