# CircuitC SPICE identity map v1

## Status and authority

Version 1 is the active reversible identity contract between a CircuitC
simulation request and SPICE/result names. Canonical CircuitC identities are
authoritative; backend names are deterministic compiled identities. The
artifact uses strict canonical UTF-8 JSON with a final newline. Unknown,
missing, or duplicate fields are invalid.

## Root object

| Field | Type | Contract |
| --- | --- | --- |
| `schema_name` | string | Exactly `circuitc.spice_identity_map`. |
| `schema_version` | integer | Exactly `1`. |
| `design` | string | The request's safe CircuitC design stem. |
| `analysis_path` | string | The request's canonical analysis path. |
| `request_sha256` | string | SHA-256 of the exact canonical request bytes, including its final newline. |
| `nets` | array | Net mappings, strictly sorted and unique by `canonical`. |
| `devices` | array | Device mappings, strictly sorted and unique by `semantic_path`. |

## Net mapping

Each `nets` element has exactly:

| Field | Type | Contract |
| --- | --- | --- |
| `canonical` | string | Canonical Design IR ASCII net token. |
| `backend` | string | Non-empty emitted SPICE node identity. |
| `is_ground` | boolean | Canonical ground status from Design IR. |

Backend node identities are injective under ASCII case-folding. Exactly one
entry is ground and maps to `0`. No non-ground entry maps to `0` or a
case-insensitive `GND` alias.

## Device mapping

Each `devices` element has exactly:

| Field | Type | Contract |
| --- | --- | --- |
| `semantic_path` | string | Canonical component semantic path. |
| `reference` | string | Unique canonical component reference. |
| `backend` | string | Emitted SPICE device identity. |

Backend device identities are injective under ASCII case-folding. Canonical
references are not required to obey SPICE device-prefix grammar; the backend
owns any deterministic mangling required by the selected simulator.

## Totality against the bound netlist

The map is total and minimal for one request's bound netlist. `devices`
contains exactly one entry for every emitted SPICE device line and no other
component. `nets` contains the canonical ground entry plus exactly every
non-ground canonical net referenced by an emitted device terminal; a declared
but unused or physical-only net is not a simulation mapping. Every device and
node token in those lines must resolve through the corresponding backend
namespace by exact string equality, every mapped device must occur exactly
once, and every mapped non-ground net must occur at least once. ASCII
case-folding is used only to prove that emitted backend identities are
injective; it never weakens exact token matching. The deterministic
`@circuitc-device` and `@circuitc-net` comments are a redundant human-readable
projection and must exactly match the standalone map, but comment parity alone
does not establish totality.

The request binds the exact netlist bytes and the map binds the exact request
bytes, so consumers verify both that digest chain and this token-level
membership before accepting the bundle.

## Failure behavior

Unsorted, duplicate, empty, case-colliding, ground-ambiguous, stale, or
malformed maps are rejected with `CC-SIM-CONTRACT-*`. Result joining is exact;
every normalized voltage signal must resolve through `nets` and every branch
signal through `devices`. Missing, wrong-namespace, or unknown mappings are
never ignored.
