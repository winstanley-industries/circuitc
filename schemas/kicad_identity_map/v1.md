# CircuitC KiCad identity map v1

## Status and compatibility

Version 1 is the active, unreleased JSON contract between CircuitC source
compilation and KiCad host-report normalization. Until CircuitC publishes this
contract, version 1 evolves in place without migrations or compatibility
shims. Semantic changes must be recorded here and in an ADR when they affect
compiler boundaries, authority, determinism, or backend ownership.

After the first release, any change to required fields, field meanings,
validation, or ordering requires a new integer `schema_version` and a parallel
schema document. Consumers reject unknown versions and any fields outside the
exact shapes below; adding an optional field is therefore a breaking change.

## Document shape

The UTF-8 JSON document is an object with exactly these fields:

- `schema_version`: the integer `1`;
- `source`: the logical design-derived basename `<design>.circuitc`, never the
  requested input path; and
- `identities`: an array sorted lexicographically by `semantic_path`, then
  `uuid`.

Each `identities` element is an object with exactly:

- `uuid`: the lowercase canonical UUIDv8 emitted into a KiCad artifact;
- `semantic_path`: the unique, non-empty canonical CircuitC semantic path; and
- `location`: either `null` for a backend-derived identity without an exact
  authored span, or the location object below.

Every emitted KiCad UUID appears exactly once. UUIDs and semantic paths are
each globally unique within the document.

## Location shape

A non-null `location` is an object with exactly these integer fields:

- `start`: zero-based inclusive UTF-8 byte offset in `source`;
- `end`: zero-based exclusive UTF-8 byte offset, greater than or equal to
  `start`;
- `line`: one-based source line containing `start`; and
- `column`: one-based Unicode-scalar column containing `start`.

`line` and `column` are presentation coordinates. `start` and `end` are the
authoritative source interval.

## Determinism and validation

The producer derives UUIDs solely from semantic identity and emits the same
bytes for equivalent canonical input. The source field is independent of the
input filesystem location. Consumers fail closed on malformed JSON, an
unknown version, key-set drift, invalid canonical UUID or semantic-path forms,
duplicate UUIDs or paths, invalid locations, a report source stem that differs
from `source`, or a UUID-bearing KiCad finding absent from `identities`.

This manifest correlates generated KiCad findings with CircuitC source; it
does not become canonical Design IR and does not weaken KiCad's ERC, DRC, or
schematic-parity authority.
