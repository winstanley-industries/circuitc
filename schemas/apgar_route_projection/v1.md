# CircuitC APGAR route projection v1

## Status and authority

This strict canonical JSON artifact binds one authenticated APGAR selected
candidate to the fresh canonical Design IR route segments and deterministic
KiCad PCB produced from them. It is evidence of lossless projection, not a
replacement for APGAR admission or supported-host KiCad DRC. CircuitC source
and canonical Design IR remain authoritative.

The encoding is compact UTF-8 JSON with one final LF. The implementation emits
the fields below in declaration order, reparses the result with unknown fields
denied by the Rust representation, and hashes the exact bytes with SHA-256.

## Root fields

| Field | Contract |
| --- | --- |
| `schema_name` | Exactly `circuitc.apgar_route_projection`. |
| `schema_version` | Exactly `1`. |
| `design_name` | Canonical Design IR name. |
| `request_path` | Authored autoroute semantic path. |
| `request_identity_sha256` | Exact authenticated request identity. |
| `request_sha256` | SHA-256 of the canonical request artifact including LF. |
| `result_sha256` | SHA-256 of the canonical result artifact including LF. |
| `selected_candidate_id` | Explicit selected APGAR 128-bit candidate ID. |
| `candidate_geometry_signature` | APGAR geometry signature. |
| `candidate_resource_signature` | APGAR resource signature. |
| `candidate_payload_checksum` | APGAR candidate payload checksum. |
| `tool` | Exact authenticated result `ToolIdentity`. |
| `segments` | Ordered one-to-one candidate primitive projection below. |
| `kicad_pcb_sha256` | SHA-256 of exact emitted KiCad PCB bytes. |

Each segment has exact fields `ordinal`, `semantic_path`, `kicad_uuid`, `net`,
`layer`, `start_nm`, `end_nm`, and `width_nm`. Ordinals are contiguous from
zero. The semantic path is `<request_path>.segment.<ordinal as eight decimal
digits>`. The KiCad UUID is the CircuitC stable route-segment UUID for that
semantic path and must occur exactly in the emitted PCB identity set. Layer is
`front` or `back`; points contain exact signed integer `x` and `y` nanometres;
width is a positive exact integer nanometre value.

Projection requires an already authenticated completed import, a fully
resolved and freshly valid Design IR, exact equality between every candidate
primitive and mapped route segment, a unique emitted KiCad identity for every
route path, and an emitted PCB containing those UUIDs. Repeated projection of
the same import is byte-identical. APGAR exact admission and a separate
supported KiCad DRC report bound to `kicad_pcb_sha256` are still required before
the route can be accepted.
