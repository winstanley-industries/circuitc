# CircuitC APGAR route acceptance v1

## Status and authority

This canonical JSON manifest is the final evidence join for one accepted
imported route. It binds exact APGAR request, result, selected-candidate,
projection, emitted KiCad board, and normalized supported-host KiCad ERC/DRC
bytes. It is evidence about one build, not a new source of design authority.

The binder independently reads every predecessor, rejects duplicate or unknown
root keys in routing contracts, recomputes every SHA-256 digest over exact
bytes, re-derives the lossless DBU-to-nanometre projection, and requires each
projected UUID exactly once in the board. Acceptance v1 additionally requires
the board's complete KiCad segment set to equal the authenticated APGAR
projection. A provisional build may still combine source-authored copper with
an imported route, but accepting such a mixed board requires a future
full-design join that can independently authenticate those authored segments.
Output is UTF-8 compact JSON with lexicographically sorted keys and one final
LF.

## Root fields

| Field | Contract |
| --- | --- |
| `schema_name` | Exactly `circuitc.apgar_route_acceptance`. |
| `schema_version` | Exactly `1`. |
| `design_name` | Exact request and projection design name. |
| `request_path` | Exact shared autoroute semantic path. |
| `request_identity_sha256` | Exact request, replay, and projection identity. |
| `request_sha256` | SHA-256 of exact canonical request bytes. |
| `result_sha256` | SHA-256 of exact canonical result bytes. |
| `projection_sha256` | SHA-256 of exact canonical projection bytes. |
| `tool_provenance_sha256` | SHA-256 of exact Bazel-generated APGAR executable provenance bytes. |
| `selected_candidate_id` | Exact explicit selected APGAR candidate. |
| `candidate` | Exact selected geometry/resource signatures and payload checksum. |
| `tool` | Exact authenticated APGAR tool identity shared by result and projection. |
| `authorities` | Five boolean results described below, all exactly `true`. |
| `kicad` | Exact host identity, filenames, and SHA-256 digests described below. |

`authorities` contains exactly `apgar_exact_admission`, `kicad_erc_clean`,
`kicad_drc_clean`, `kicad_schematic_parity_clean`, and
`kicad_unconnected_clean`. APGAR admission additionally requires supported hard
constraints satisfied, no unsupported rules remaining, exactly two connected
intended terminals, and exact validation status `passed` in the selected
candidate.

`kicad` contains exactly `host`, `pcb_filename`, `pcb_sha256`,
`schematic_filename`, `schematic_sha256`, `drc_filename`, `drc_sha256`,
`erc_filename`, and `erc_sha256`. Host is exactly the matching normalized
ERC/DRC KiCad 10 identity. Each normalized report contains the SHA-256 digest
of the private immutable source snapshot hashed before and rechecked after
KiCad execution and report normalization. The DRC report must name and hash
the bound PCB and contain no violations, unconnected items, or
schematic-parity findings. The ERC report must name and hash the matching
schematic and every sheet must contain no violations. The PCB digest must equal
both the projection field and exact board bytes. The parsed KiCad segment UUID
set and cardinality must equal the projection exactly, and every projected
route UUID, net, layer, start, end, and width must match its one parsed KiCad
segment. Acceptance rejects any top-level KiCad arc, via, or zone because those
routed-copper forms are outside the authenticated initial projection contract.

Acceptance v1 pins the exact KiCad ignored-check policy. ERC may ignore only
`footprint_filter`, `four_way_junction`, `simulation_model_issue`, and
`single_global_label`; DRC may ignore only `footprint_filters_mismatch`,
`footprint_type_mismatch`, `missing_courtyard`,
`track_not_centered_on_via`, and `tuning_profile_track_geometries`, with the
KiCad 10.0.5 descriptions recorded by the binder. No electrical, connectivity,
clearance, or schematic-parity rule may be ignored.

The binder accepts only the initial request's exact four KiCad host-rule
boundaries: board-edge clearance, courtyard clearance, KiCad custom rules, and
schematic/board parity. The host test invokes KiCad DRC with schematic parity
enabled before constructing this manifest. The binder invokes CircuitC's
shared strict Rust verifier to recompute the selected candidate ID,
associations, resources, metrics, signatures, checksum, logical byte count,
and exact CPU provenance from the request, result, and Bazel-generated
executable-provenance artifact.
